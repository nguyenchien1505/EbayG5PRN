# B02 security contract

- Account resource: `/Account/Details/{id}` loads the database row and permits only the authenticated owner. Missing and foreign accounts both return 404. No Admin bypass.
- All authenticated access by Admin requires a direct remote IP in `Security:AdminAllowedAddresses`, default IPv4/IPv6 loopback. Missing IP fails closed. Forwarded headers are not trusted; deployed proxy/network configuration belongs to F01.
- Named Buyer, Seller and AdminDemo policies support later modules; their object checks must be implemented with each module. B05 covers address/checkout confirmation ownership; purchase/sales history, state transitions, chat and dispute authorization remain for their respective tasks.
- Cookies are revalidated against database ID, role and nonempty password on each request. Deleted accounts, removed credentials and changed roles require login again. Password changes and copied cookies after logout are not globally revoked yet.
- Existing global MVC antiforgery remains mandatory on unsafe methods. Forbidden responses return 403. Exceptions return generic 500 in every environment.
- Login/register POST share a fixed window of 10 requests/minute per direct IP, no queue, 429 on excess (including invalid CSRF). GET and logout are unaffected. This is single-process demo protection; distributed limits and proxy trust remain F01/F02.
- B05 checkout/add-address/confirmation require Buyer policy; Buyer ID comes exclusively from principal. Address selection and confirmation check owner; missing/foreign confirmation returns 404, pages no-store. Price/Buyer/payment-method overposting is ignored; SQL/HTTP evidence in [B05](../evidence/B05.md). Chat/dispute/order state transitions remain for their respective tasks.
- Files: Web Security/AccessSecurity.cs, Program.cs, AccountController.cs; SQL-backed HTTP security tests. No schema changes, new business module or UI design.
- B06 [ORDERS](ORDERS.md): Buyer purchase/Seller sales policies; detail checks BuyerId or immutable SellerId snapshot, no Admin bypass. Seller Ship/Buyer Receive principal-only, unsafe CSRF, foreign/missing404, wrong state409, no-store. History exposes only bounded owned orders, no credentials/emails; shipment/payment updates atomic with idempotent retries. Product seller reassignment grants no access to historical order.
- C01/C02 [CHAT](CHAT.md): composite membership FK/checks plus SQL service/principal authorization and owned REST. API unauthenticated401 without redirect, wrong endpoint role403, foreign/missing/Admin object404; service rechecks current role/nonempty credential for each owned operation. New sends require active peer; authorized retry/history remains available if peer becomes inactive. No client sender/receiver/reader/price/trace authority.
- Chat JSON writes require X-CSRF-TOKEN via shared antiforgery; form MVC checks stay mandatory. All chat responses no-store, generic model/service/server errors; declared/actual body bounded32768 bytes. SQL locks membership/context during writes; metadata-only receipt logs after commit; UTF-16/hash/idempotency and read cursor constraints verified in [C02](../evidence/C02.md). Hub Origin/recipient subscription guards C03, deployed HTTPS/WSS F01/F04 and reconnect/outbox C05 remain unimplemented; do not claim those from REST tests.
